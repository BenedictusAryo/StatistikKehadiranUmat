# Quickstart

This page is the entry point for an agent new to the **Statistik Kehadiran Umat**
repository. It routes to every OpenWiki documentation page by topic domain.

## Project Overview

The system is a real-time, offline-first attendance counting and survey application
for **Gereja St. Matius Penginjil, Paroki Bintaro -- Keuskupan Agung Jakarta (KAJ)**.
It runs a **FastAPI (Python)** backend with a **React + Zustand + Tailwind CSS**
frontend, backed by SQLite (dev) or MySQL (production). Three user groups interact
with the system through distinct interfaces:

- **Petugas Kiosk (ushers)** -- tablet-based door kiosks, authenticated via QR token, no login required
- **Videotron / Public Display** -- live congregation-facing display shown on church projectors
- **Admin & Litbang Dashboard** -- authenticated event management, live monitoring, reports, and evaluations

## Routing

### Kiosk Pos Flow (Usher Entrance Workflow)

The kiosk is an offline-first tablet interface at each church door. An usher scans
a QR code bearing a unique pos token, sees two large touch buttons (Umat Paroki
Bintaro vs Umat Luar Paroki), and taps to record each arriving congregant.

> **Start here:** `/openwiki/workflows/kiosk-counter.md` -- step-by-step operator workflow
>
> **Underlying sync design:** `/openwiki/concepts/offline-sync.md` -- Zustand offline queue, idempotent UUIDs, background auto-sync
>
> **End-to-end data flow:** `/openwiki/concepts/attendance-flow.md` -- tap to server to cache to display

### Videotron Public Display

A real-time, congregation-facing display shown on church projectors during mass.
It polls live stats every 6 seconds, shows odometer-style totals, building
breakdown, and a time-series arrival chart. Has three view modes: SPLIT,
NUMBERS, and CHART. Capacity warnings trigger at 75% and 95%.

> **Start here:** `/openwiki/integrations/videotron.md` -- display modes, chart, clock, capacity alerts
>
> **Backend cache layer:** `/openwiki/architecture/backend-overview.md` -- TTL cache (3s), `/api/stats/{event_id}/live` endpoint

### Admin / Litbang Dashboard

Authenticated dashboard for event lifecycle management, real-time monitoring,
official A4 Litbang report print view, evaluation notes editor, CSV export, and
master position (door) catalog management.

> **Start here:** `/openwiki/integrations/admin-dashboard.md` -- event listing, live monitoring, reports, QR codes, CSV
>
> **Event creation workflow:** `/openwiki/workflows/create-event.md` -- SCHEDULED to OPEN to COMPLETED lifecycle
>
> **Access control:** `/openwiki/architecture/authentication.md` -- JWT auth, ADMIN vs LITBANG roles

## Local Development Quickstart

```bash
# 1. Setup
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
cp .env.example .env

# 2. Database migration
alembic upgrade head

# 3. Build frontend
cd frontend && npm install && npm run build && cd ..

# 4. Start server
uvicorn app.main:app --reload --port 8000

# 5. Run tests
pytest tests/
```
